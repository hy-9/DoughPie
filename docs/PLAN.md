## 1. 项目概述

- **产品名**：豆排排（DouPaiPai）——豆腐 + 一排排码整齐（通俗 + 整理规划意象）；
  **英文名 DoughPie**（dough 面团 ≈ 豆 + pie 派 ≈ 排，谐音 + 双食物）；
  英文代号/包名 `doughpie`；MCP 桥接包保留 `todomcp-mcp` 名
- **定位**：个人/小团队（≤20 人）自用多人协作待办工具
- **端**：Web（React SPA）、移动端（Expo RN）、PC 桌面（Tauri 壳）、MCP（Server 优先，Client 缓做）
- **核心能力**：共享清单/看板、任务分配与流转、讨论区与@提及、动态流、细粒度权限、
  实时同步（数据+动态+在线状态）、通知系统（分级/确认/推送）
- **明确不做**（最终四条）：IM 聊天、离线写入（CRDT）、SaaS 多租户、邮箱通知
- **认证**：双模式用户体系——本地自含（可完全独立运行）+ 可选接入统一用户中心
  UC（`hy-9/userSystem`，本地 `C:\code\Rust\salvo\hello`，Rust+Salvo，默认 `0.0.0.0:8698`）。
  详见 [backend.md](./backend.md) §2

## 4. 实时同步协议

- **events 表一石四鸟**（断线补齐 / 动态流 / 审计 / **通知引擎数据源**）：
  `id(bigserial 全局单调=游标), workspace_id, actor_id, type, entity, entity_id, payload(jsonb), created_at`
- 写路径：乐观更新 → `PATCH` 带 `If-Match: version` → 事务内 [乐观锁校验(不符 409) → 更新 → 写 events] →
  提交后向 `workspace:{id}` 房间广播 → 其他端按实体 key 精确失效 Query 缓存
- 断线恢复：socket 携带 lastEventId；重连 `GET /events?cursor=` 补齐。**正确性只依赖游标**
- presence：连接即在线（心跳 15s/超时 30s）；P1 加 active_task_id 上报
- 排序冲突接受后写者胜（弱一致字段）

## 5. 通知与提醒系统

### 5.1 类型 × 等级 × 已读行为矩阵（默认映射，用户可改）

| 类型 | 触发 | 默认等级 | 已读方式 | 可关闭 |
|---|---|---|---|---|
| mention 提及 | 评论/描述中 @你 | 🔴 高 | **手动点「收到」确认**，永不自动已读 | 不可关 |
| assigned 分配 | 被设为负责人 | 🔴 高 | 手动已读 | 不可关 |
| overdue 逾期 | 到期未完成（次日提醒） | 🔴 高 | 手动已读 | ✅ 按任务关 |
| progress 推进 | 关注的任务状态/字段变更、新评论 | 🟠 中 | **打开对应任务详情即自动已读** | ✅ 任务级 全部/仅提及/静音 |
| due 截止临近 | T-24h / T-1h | 🟠 中 | 手动已读 | ✅ 任务级开关 |
| incomplete 未完成汇总 | 每日一次汇总（§5.7） | ⚪ 低 | 手动已读 | ✅ 任务可设置排除 |
| system 系统 | 移出工作区/角色变更/实例管理操作 | 🟠 中 | 手动已读 | 不可关 |

### 5.2 等级体系与自定义映射（用户选定：可自定义）
- 三级固定刻度（🔴高/🟠中/⚪低），上表为默认映射；设置页可按类型调整等级，
  存 `user_notification_prefs.type_levels`
- **推送绑定（用户选定）**：🔴 = 系统推送 + 站内；🟠 = 站内 + 推送可选；⚪ = 仅站内。
  改等级即改推送策略（防低优轰炸导致 App 通知权限被整体关闭）

### 5.3 关注者模型（用户选定：自动+手动）
- **自动关注**：创建任务、被分配、评论过、被@过 → 自动成为该任务关注者
- **手动**：任务详情「关注/取消关注」；`notify_mode`: all / mentions_only / muted
- 任务被推进 → 向 `all` 档关注者发 progress 通知（发起者本人除外）
- 通知引擎 = events 表的第四个消费方：事务提交后按事件类型向关注者扇出

### 5.4 已读模型（按任务区分）
- 每条通知独立 `read_at`；通知中心**按任务分组聚合**（同任务 N 条折叠为一组，
  显示未读数徽标 + 类型图标），支持组级「全部已读」、等级/类型筛选（P1）
- **自动已读**：打开任务详情 → 该任务的 progress 类通知全部置已读；
  mention 类**不**自动已读，必须点「收到」
- 每条通知都是**深链**：点击直达任务详情（评论通知锚定到对应评论楼层）

### 5.5 提及确认闭环（不阻塞流程，24h 节流）
```
A 在评论中 @B @C @D → 三人收到 mention 通知（待确认）
评论区显示：@B✅已确认14:32  @C✅已确认09:15  @D⏳待确认
任务详情显示提及进度 2/3；发起者可点「再提醒」（同一发起人对同一提及 24h 限一次）
确认记录进 events（动态流可见「B 确认了提及」）；未确认不阻塞任何任务流转
```

### 5.6 任务级通知设置
任务详情 ⋯菜单 → 通知设置：`notify_mode`（全部/仅提及/静音）+ 关闭逾期提醒 + 未完成汇总设置。
存 `task_watchers`。

### 5.7 未完成汇总（每日一次默认，任务可设置）
- 每日 9:00 汇总「你有 N 个未完成/逾期任务」→ 深链进智能视图；**吸收原 P2「每日摘要」**
- 任务级设置：是否纳入汇总（`mute_incomplete`）、可自定义提醒时间（P1）

### 5.8 提醒引擎与推送扇出
- pg-boss 每分钟扫描 `remind_at <= now() AND status != 'done'` → 一次性投递 job（notifications 去重）
- 扇出：Expo Push（移动）+ web-push VAPID（Web/PWA）+ socket→本地通知（桌面在线）
- 扇出时按 §5.2 的等级→推送策略过滤；实现细节见 backend.md §6

## 6. 讨论区与状态机

### 6.1 讨论区（P0-17 基础版 → P1 完整版）
- 任务详情下半区为讨论时间线：评论 + **一级回复**（楼中楼，不深嵌套）
- @提及（接 §5.5 确认闭环）、编辑/删除（tombstone）、附件引用（多态）
- **每条评论记录发表时的任务状态**（`state_at_comment`）：任务流转多少次，
  各状态下的讨论都带状态徽章永久沉淀，支持按状态过滤（P1）
- **依赖倒置说明**：提及确认进 P0 ⇒ 评论必须连带进 P0（用户已接受 P0 +1 周）

### 6.2 状态机四态预埋（P0 契约即定，P1 开 UI）
- 枚举 P0 即四态 `{todo, doing, review, done}`；**P0 UI 渲染三列**：review 态任务显示在
  「进行中」列并带「待验收」徽章；P1 升级为独立第四列 + 流转操作
- 转化 = 状态机扩展（用户选定解释 A）：流转动作进 events，评论区按状态徽章分段保留
- 转自由不强制（todo 直达 done 合法）；自定义状态列 → P2
- 预埋收益：P1 不动 zod 枚举/看板契约/智能视图/重复任务语义/仪表盘/events 类型

### 7.3 甘特 L3 分片（P1 长杆，用户坚持 L3，分片隔离风险）
| 分片 | 内容 | 估时 | 依赖 |
|---|---|---|---|
| G1 | `start_at` 字段 + 时间轴视图 + 拖拽改期 | 3-4d | 可独立交付 |
| G2 | 依赖表（仅 FS）+ 连线渲染 + **DFS 防循环**（成环 409） | 4-6d | G1 |
| G3 | 级联改期：拖前置→后继自动顺延；**批次记 batch_id，一键撤销** | 2-3d | G2 |
| G4 | 关键路径：DAG 最长路径计算与高亮（纯函数） | 2d | G2 |
| G5 | 基线快照（手动命名）+ 基线条叠加 + 偏差天数 | 2-3d | G1 |
- **G1 先行，G2 之后随时可冻结**；依赖/级联/关键路径全部纯函数 + 规格推导测试先行
- start_at 为空时甘特条用 `[created_at, due_at]` 兜底；移动端不做甘特

### 7.4 工作区 Wiki（P1，说明首页 + 多文档合体）
- `wiki_docs` 树状组织（parent_id），**指定一篇为工作区门面（说明首页）**
- Markdown（CodeMirror 编辑 + react-markdown 预览，非 TipTap 富文本）

- 移动端只读 + 简编

### 7.5 仪表盘（P1，5 图 + 自定义卡片）
- 五图：完成趋势 / 按成员统计 / 状态·优先级分布 / 逾期榜 / 燃尽（recharts）
- 卡片框架：注册表式卡片，显示/隐藏/拖拽排序，布局存 `user_preferences`（服务端持久化，多端一致）

| 移动端边界 | 甘特不做；Wiki 只读+简编；日历议程列表；仪表盘简版（详见 mobile.md §3） |

## 9. AI 开发模式（六条军规）

> 工程纪律全量见 [conventions.md](./conventions.md)（Git/分支、TDD 分级、AI 使用规范、测试规范）。

1. 合同先行：packages/shared 的 schema/事件/枚举是公共输入，冻结后变更走显式流程
2. 门禁代替纪律：CI 跑 tsc --strict + oxlint + 单测 + 构建；工作包必须变绿才算完
3. 每包带 DoD 验收清单，逐条勾选
4. 关键算法测试从本规格推导、先于实现（重复任务/排序间隙/权限矩阵/防爆破/依赖防环/级联/关键路径）
5. 仓库即记忆：规格摘要与决策记录落 docs/，新会话可接续
6. 评审分级：规格与测试重点看，实现扫 diff，边界靠门禁
